# Linux 06 — Security Basics

## Overview

Linux is widely used in servers, cloud environments, networking infrastructure, cybersecurity tools, and security labs.

Understanding Linux security means understanding how users, permissions, processes, services, files, and logs work together.

This note summarizes the main Linux security concepts I have learned so far.

---

## 1. Principle of Least Privilege

The Principle of Least Privilege means that users, applications, and processes should receive only the permissions they actually need.

For example, if a user only needs to read a file, there is usually no reason to also provide write or execute permissions.

```text
Required Access
      ↓
Give only that access
      ↓
Reduce unnecessary privileges
```

This can reduce the impact of mistakes, compromised accounts, and vulnerable applications.

---

## 2. File Permissions

Linux permissions control access to files and directories.

The main permissions are:

```text
r = read
w = write
x = execute
```

Permissions are assigned to:

```text
Owner
Group
Others
```

Example:

```text
-rw-r-----
```

means:

```text
Owner  → read + write
Group  → read
Others → no permissions
```

Permissions can be modified using:

```bash
chmod
```

For example:

```bash
chmod 600 secret.txt
```

gives the owner read/write access while removing permissions from the group and others.

---

## 3. Avoiding Unnecessary `777`

A permission such as:

```bash
chmod 777 file
```

gives:

```text
Owner  → read + write + execute
Group  → read + write + execute
Others → read + write + execute
```

This may provide much more access than necessary.

Using `777` simply because a program is producing a permission error can create security problems.

The better question is:

> What permissions does this file or application actually require?

---

## 4. Users and Groups

Linux can support multiple users with different access levels.

Useful concepts include:

```text
UID → User ID
GID → Group ID
```

Users can also belong to groups.

Groups make it possible to manage shared access to resources without giving the same permissions to every user on the system.

Useful commands include:

```bash
whoami
id
```

---

## 5. Root and Elevated Privileges

`root` is the highly privileged Linux superuser.

Administrative privileges can allow changes to important parts of the system.

Because elevated privileges are powerful, they should only be used when necessary.

A compromised application running with limited privileges may have limited impact.

A compromised application running with excessive privileges may have significantly more access.

---

## 6. Processes

A process is a running program or task.

Processes have identifiers called:

```text
PID
```

or:

**Process ID**

Processes can be inspected using commands such as:

```bash
ps
ps aux
```

Large process lists can be filtered:

```bash
ps aux | grep "name"
```

Process monitoring can help identify unexpected or suspicious activity.

However, an unfamiliar process is not automatically malicious.

It needs to be investigated.

---

## 7. Network Activity

Processes can communicate over networks.

Useful networking tools can help investigate:

- IP addresses
- Connections
- Listening ports
- DNS
- HTTP
- Network interfaces

Commands may include:

```bash
ifconfig
ip addr
ping
curl
nslookup
dig
netstat
ss
lsof -i
```

A security investigation may need to connect a network connection back to the process responsible for it.

Conceptually:

```text
Network Connection
       ↓
IP + Port
       ↓
Process
       ↓
User
```

---

## 8. Logs

Logs record events generated by operating systems, applications, and services.

Security-relevant logs may contain information about:

- Login attempts
- Authentication failures
- Application errors
- Network activity
- System events
- Service activity

Logs can contain thousands or millions of entries, so command-line filtering becomes useful.

For example:

```bash
grep "FAILED" security.log
```

could isolate failed events.

Commands can also be combined:

```bash
grep "FAILED" security.log | wc -l
```

to count matching events.

---

## 9. Searching Logs

My earlier Linux lab used:

```bash
grep "FAILED" notes.txt
```

to extract failed login events.

I then used:

```bash
grep "FAILED" notes.txt | awk '{print $3}' | sort | uniq -c | sort -nr
```

to extract usernames and count how many failed attempts were associated with each one.

This introduced the basic idea of turning raw logs into useful security information.

---

## 10. Authentication and Authorization

### Authentication

Authentication answers:

> Who are you?

Examples include:

- Password
- Security key
- Biometrics
- Multi-factor authentication

### Authorization

Authorization answers:

> What are you allowed to do?

Linux file permissions are an example of authorization.

A user may successfully authenticate but still receive:

```text
Permission denied
```

if that user is not authorized to access a resource.

---

## 11. Privilege Escalation

Privilege escalation involves obtaining a higher or different level of access.

### Vertical Privilege Escalation

```text
Normal User
     ↓
Higher Privileges
```

### Horizontal Privilege Escalation

```text
User A
     ↓
Unauthorized access to User B's resources
```

When privilege escalation occurs without authorization, it represents a security issue.

Misconfigurations, excessive permissions, or vulnerabilities can sometimes contribute to privilege-escalation risks.

---

## 12. Sensitive Information

Sensitive information should not be stored carelessly.

Examples can include:

```text
Passwords
API keys
Access tokens
Private keys
Credentials
Configuration secrets
```

This is especially important when using Git and GitHub.

Secrets should not be committed to public repositories.

Files containing local credentials or sensitive configuration may need to be excluded using:

```text
.gitignore
```

---

## 13. Why `.gitignore` Matters

A `.gitignore` file tells Git which files or directories should not normally be tracked.

Examples may include:

```text
.venv/
.env
__pycache__/
*.pyc
.DS_Store
```

A `.env` file is commonly used by applications to store environment-specific configuration and may contain secrets.

If a real credential is accidentally committed to GitHub, simply deleting the visible file later may not be enough because Git history can retain previous versions.

The exposed credential should be treated as compromised and rotated/revoked.

---

## 14. Security Is More Than Tools

One important lesson from these Linux topics is that cybersecurity is not only about learning commands or security tools.

A command such as:

```bash
grep
```

is not specifically a cybersecurity tool.

However, it becomes useful in security when it helps analyze logs or investigate data.

Similarly:

```bash
ps
```

is a normal system command, but it can help investigate running processes.

The important skill is understanding how normal system functionality can be used during security analysis.

---

## 15. Basic Investigation Mindset

A simple investigation process can look like:

```text
Observe
   ↓
Collect information
   ↓
Filter relevant data
   ↓
Verify assumptions
   ↓
Investigate unusual results
   ↓
Determine context
   ↓
Take appropriate action
```

One thing I learned during the earlier labs was not to assume a command is broken when the output is different from what I expected.

Sometimes the input data or system configuration is simply different from what I assumed.

Verification is important.
